# Android 多角色朗读

后续原生逐章分析、自动跨章和正文位置保存见 [ANDROID_READING_SPEECH.md](ANDROID_READING_SPEECH.md)。下文为初次接入记录。

2026-11-03，在 `codex/android-phone-prototype` 接入手机多角色朗读，复用桌面的个人 AI 角色分析和 Azure 情绪设置。

## 使用

1. 在“设置 → AI 服务”添加自己的 Gemini 模型，并将其选为“AI 辅助模型”。角色分析沿用该分配，也兼容已有的个人 OpenAI 兼容模型配置。
2. 安装并配置 Azure / MiMo 语音插件。打开书内朗读面板，选择云朗读服务、旁白音色，开启“AI 多角色朗读”。系统离线朗读保留单音色模式。
3. 分别选择男声、女声和童声，可混用 Azure 与 MiMo。未选择或已经不可用的角色音色使用旁白。Azure 音色可配置其支持的情绪与强度；选择相同 Azure 音色时共享该音色的偏好。
4. 点击开始，先分析本章当前可见位置之后的文字，再交给原生队列播放。分析期间可停止或切换朗读服务以取消；关闭面板保留分析，退出阅读器取消。分析阶段需要 WebView 继续运行；完成后的播放队列可在后台继续。

多角色开关按书籍保存，角色音色沿用桌面的 `multiRoleMale/Female/ChildVoice` 和 `Engine` 偏好。手机当前服务的音色作为旁白，使用已有 Android 音色偏好。返回面板会保留所选音色。

## 文字、播放与取消

使用 `Intl.Segmenter` 分句，保留标题、数字、标点和原始文字；模型只提供 narrator / male / female / child 标签，不使用模型改写后的正文。沿用现有 5 万 UTF-16 字符、2000 条分析输入的上限及每批最多 8 条的请求方式。模型漏标时使用旁白并显示提示；格式错误、模型服务繁忙或超限时结束分析并允许重试，不自动启动单音色播放，也不自动重试付费请求。

原生队列只合并相邻同角色文字，每段最多 1200 个 UTF-16 字符，拆分长句时保留角色且不切断代理对。每个角色的 Azure/MiMo 配置在开始时验证，切段后由对应提供器生成音频；Azure 使用合成语速，MiMo 使用本机播放语速。暂停继续、上一段/下一段、通知媒体控制和音频焦点处理沿用现有服务。单会话仍最多保存两份临时音频，停止和结束时关闭所有角色请求并清理。

前端分析同时校验取消信号、播放修订号和当前书籍实例。停止后迟到的模型回复不会创建原生播放队列；取消底层原生 HTTP 不保证服务端停止计算。原生音频回调继续校验会话、队列和片段标记，旧角色音频不会推进新会话。

自动跨章、正文跟读翻页、跨进程恢复，以及系统离线音色与云音色混合的多角色队列仍未接入。真实 Gemini、Azure、MiMo 密钥、额度和音色品质需要在应用内配置后验证；本批协议测试使用隔离服务与合成音频。
