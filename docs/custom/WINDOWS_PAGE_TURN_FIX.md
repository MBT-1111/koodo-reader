# Windows 连续翻页卡死修复

2026-11-03，`custom/dev`。

## 触发与修复

Windows 配置文件可读写、但被其他文件句柄禁止重命名时，`electron-store` 的原子替换会抛出 `EPERM`。翻页后的进度保存异常跳过了输入锁释放，导致后续滚轮及左右键一起失效；重新加载页面时，启动设置写入也可能抛错，使 React 页面无法启动。

- 主进程继续优先使用原来的原子保存。仅在 Windows、明确的配置文件目标重命名返回 `EPERM` / `EACCES` / `EBUSY` 时，先将上一份完整配置写入并刷盘到 `config.json.recovery`，再覆盖并刷盘当前文件。
- 恢复文件保存失败时不动主文件；主文件写入失败时尝试回写上一份配置，并保留恢复副本、继续上报失败。配置工具初始化遇到不完整 JSON 时，可用完整恢复副本还原；有效的新配置不会被旧备份覆盖。
- 不对其他 I/O 错误或其他重命名目标启用回退，不将真正的保存失败伪装为成功。
- 相同值的设置写入、删除已不存在的键不重复写盘。
- 复用同一个翻页锁，在 `finally` 中释放，覆盖文档/窗口键盘、滚轮和触摸路径；即使翻页或保存失败，后续输入也可以重试。

配置格式、数据库、阅读进度格式和原生依赖保持兼容。没有读取或修改混淆引擎源码。
