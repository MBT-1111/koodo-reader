# 自有同步协议 v1

这是尚未发布的 Windows 实施协议；未来移动客户端必须实现相同校验和语义，不能直接使用官方移动端或官方 SyncHelper。后续不兼容变更须升版本。

## 标识与传输

- Book ID：完整文件 SHA256。出版物 identifier/ISBN 是 metadata，不用来自动合并不同文件/版本。文件不可用且没有旧映射的记录暂不发送。
- Note/Bookmark ID：每个本地实体独立 UUID；原始 upstream key 只留在本机映射中，不假设时间戳全局唯一。未绑定本机书籍的远端实体保留待应用，不创建虚构书籍。
- Shelf/Tag ID：UTF-8 名称 hex；成员按名称 ID/书籍 ID 独立记录。
- Device ID：每书库/账户/同步空间的检查点独立 UUID。不要跨设备复制 custom-sync 检查点；新设备应独立登录并导入相同文件。
- 云目录：`KoodoReaderCustom-v1-<namespace>`。快照名为 `<device UUID>-<16位序号>-<内容hash前16位>.json`。
- `default` 仅是同步空间的默认名称，不表示登录状态；相同账户/文件夹中的相同空间用于设备间合并，不同空间互相独立。MEGA 与文件夹各保存一个连接，兼容原单连接设置；顶部同步每次明确选择目标，设置页只操作当前显示的连接，未保存修改时禁止同步。断开一个连接不清除另一个连接。
- 自动同步一次只启用一个连接，为另一个连接开启时关闭原连接的定时同步。手动选择目标不改变自动同步目标。
- 快照信封包含 format、version、deviceId、sequence 和 entries。每个修订包含 UUID、向量 clock、kind、deleted 和白名单 value；未知协议、实体/字段、非法数值、原型键、过大快照和相同 UUID 的异内容均拒绝。

每次保存不可变快照，读取每设备最新序号的所有同代文件，合并不同设备和同代分叉。上传后校验新文件字节，保留本设备最近三代；不删其他设备当前快照或实体删除标记。MEGA 旧文件移至回收站，用户自行管理账户回收站配额。未知/损坏历史保留调查。

## 因果、冲突和删除

向量支配的旧修订被新修订取代；并发修订全部保留。非统计冲突暂按删除优先、UUID 稳定顺序选一个值，设置显示所有候选，可明确选择版本生成支配全部候选的新修订。暂选不等于清掉其他冲突版本。

新设备已有且与远端完全一致的数据作为共享基线，不产生额外伪编辑。真正本地编辑在合并远端前记录，避免把刚读取的远端版本错误当成已被本地编辑覆盖。单独保存“实际应用过”的因果上下文；上传后应用失败不会把未应用的远端数据当作用户已确认。测试覆盖改名、并发编辑、删除恢复、上传期间编辑、重复/乱序投递。

笔记/书签、书架、成员、标签、收藏和回收站状态传播删除；书籍二进制永不随 tombstone 删除。删除标记不按时间过期，避免离线设备重现旧数据。被删除书架的成员记录保留，但不恢复父书架。

## 统计

累计/每日统计各有 `{baseline, devices}` 计数器。首次旧统计的 baseline 取各设备最大值，以避免把已经拷贝的历史重复相加；此规则不能推断两份旧历史有多少独立部分。建议先由主设备初始化同步空间，新设备从空统计接入。

接入后，本机相对上次实际应用值的正增量累加到本设备分量，合并对每设备取 max，再求 baseline 与分量之和。重试、重复下载、导入总数不再次计时。协议 v1 不把本地减少/清空视为远端统计复位；如需全新统计，用新同步空间初始化。减计数/统计删除需未来定义 reset epoch 后升版本，不伪装成已经支持。

## 恢复与边界

上传前保存原始业务数据和前一检查点，原子临时文件写入、flush 后 rename；上传前持久化 outgoing 修订，断网后可重试。应用前再次检查本地未变。新备份位于当前书库存储目录下的 `sync-backups/<scope>`，每书库/连接/空间保存二十份同步前备份及二十份恢复前备份；恢复兼容读取原 `profile/custom-sync/backups/<scope>`，原备份不移动或删除。账户和检查点仍存独立 profile，凭证不随备份导出。“打开本地同步备份”打开当前书库的备份目录；“打开同步目标文件夹”打开保存的文件夹连接下的协议目录。

本地写入前另持久化 prepared/applying 阶段标志。渲染进程在 applying 阶段消失时，后续同步暂停并要求本地恢复，不能把半完成的导入当成新编辑上传；已完全回滚的尝试才清理标志。备份带内容 checksum，恢复前核验。

恢复最近同步前备份是本地操作，会暂停自动同步，不回滚云端时钟和计数器；再次同步可能恢复云端统计。恢复不能改变本机书籍文件、封面或书籍集合；集合已变化时拒绝自动恢复，保留备份供人工处理。

MEGA 会话仅在主进程通过 safeStorage 加密存储，原密码/验证码从序列化会话中移除；状态只返回连接摘要（邮箱、文件夹、空间与定时设置），错误只传固定代码，区分账户、网络、配额、文件夹和本地文件错误。保存账户不代表网络始终可用，设置提供连接测试。重建会话后必须 reload 文件树，通过 root.mkdir 创建目录。MEGA 的登录和后续请求共用注入的 Electron `net.fetch`，使用应用/系统代理，避免 Node 全局 fetch 绕过应用代理。请求与 Provider 操作有超时，结束时停止本地轮询。适配器使用[MEGAJS 公开 API](https://mega.js.org/docs/0.17/api)，不使用 Koodo 官方付费服务。

MEGA 的完整文件列表在交给 SDK 导入前按父子依赖排序。本地锁定的 SDK 会跳过尚未导入父节点的子节点关联；直接依赖返回顺序会漏掉已存在的同步目录，重试可能重复建目录。循环或重复节点标识会停止同步，不能将无效目录树当作空目录。已有同名目录继续跨目录读取快照，不自动删除目录。

MEGA 的 `f` 列表可能是缓存基线，必须从其 `sn` 消费 `sc` 变更，直到返回等待地址后才能查找同步目录。客户端禁用后台 keepalive，改为在每次恢复会话后有限追赶，再交给 SDK 原有处理器应用变更；不进入长期轮询。缺失序号、无效响应或追赶失败均停止操作，不能将旧列表当作当前目录创建新目录。参见 [MEGA SDK 关于缓存列表和变更包的说明](https://github.com/meganz/sdk/issues/2759)。

MEGAJS 为分块上传手动设置的 `Content-Length` 必须从注入的传输层移除；Electron `net.fetch` 会以 `net::ERR_INVALID_ARGUMENT` 拒绝该请求头，长度应由实际请求体推导。保留其他请求头、原始字节和取消信号。

文件传输显式使用 HTTPS、两个连接与错误直接上报，避免单连接流读取错误悬挂以及 SDK 的后台分块重试。请求仍有 30 秒超时；操作允许连续正常请求超过一分钟，60 秒无新请求或累计 150 秒会中止，早于 180 秒会话租约到期。失败或完成时取消该操作的剩余网络请求，并停止本地 API 轮询；不注销已保存的登录会话。

当前限制：单快照 20 MiB、合并读取 100 MiB、最多 1024 个设备代次/128 个并发修订、十万实体；损坏/越界时停止。文件夹 Provider 验证了真实磁盘读写。MEGA 的无网络回归使用实际 SDK 执行加密、建目录、分块上传、恢复目录树及下载校验，覆盖乱序列表、缓存基线与变更追赶、失败重试复用目录、下载响应中断、已有重复目录、上传请求头、慢请求与超时取消。Electron smoke 另通过实际 `net.fetch` 和回环 HTTP 服务校验分块字节，待云端新构建运行。挂载同步文件夹若尚未完成外部客户端传输，下一次同步会再合并；不把暂时缺失当作删除。
