# 阶段计划

交接时仅授权 Phase 0。2026-10-31 用户继续授权自主完成 Windows 修改，本轮据此推进桌面所需的 Phase 1–4 与部分 Phase 7；不自动延伸到移动开发、真实数据改动或 Git/发布操作。

| 阶段 | 目标 | 验收门槛 |
| --- | --- | --- |
| 0 | 工程、Git、环境、验证和文档基线 | 如实记录成功、失败、范围调整；不更改业务代码或真实书库 |
| 1 | 数据契约与真实持久化验证 | 仅用隔离样本确认数据库、ConfigService、统计、删除、标识、凭证；形成可追踪写入矩阵 |
| 2 | 自有协议与 MEGA 原型 | 验证跨设备标识、冲突、断线重试、幂等、删除传播、协议升级、备份和凭证排除 |
| 3 | 桌面同步接入 | 保留官方功能，在少量边界接入；验证失败恢复与数据回滚 |
| 4 | TTS 语音与情绪分离 | 按语音能力显示情绪；验证 SSML/转义、语速、缓存、暂停恢复与多角色兼容 |
| 5 | 移动端原型 | 优先 Android 真机验证引擎、桥接、存储、后台音频和同步；再决定框架 |
| 6 | Android/iOS 功能移植 | 按平台优先级核对桌面阅读行为；iOS 资源和发布条件另行确认 |
| 7 | 更新兼容与长期维护 | upstream 升级清单、自动回归、独立更新与可恢复构建 |

## Phase 0 当前范围调整

- 保留现有 `custom/dev` 与 upstream 推送禁用设置。
- 核查安装脚本后安装锁定依赖，执行类型检查和已有 Vitest 单元测试。
- 按用户最新要求跳过 Web 构建，不安装 Windows 编译组件，不在本地构建安装包。
- 桌面打包放 GitHub 云端；本轮检查现有工作流，不触发工作流、不上传或发布产物。
- 已安装 Windows 2.4.6 只作为只读基线；后续可研究备份后替换构建资源的调试流程。
- Azure-MiMo-TTS-Chrome 仅审计可借鉴逻辑，不实施 TTS 或新增 MiMo Provider。
