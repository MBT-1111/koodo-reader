## 数据安全事实与候选隔离方案

源码事实：`main.js` 在模块顶层先创建 `electron-store`，再读取 `app.getPath("userData")`；默认数据目录为 `<userData>/uploads/data`，TTS 缓存为 `<userData>/uploads/tts`。`src/utils/common.ts:getStorageLocation` 优先使用已保存的 `storageLocation`。启动时还会申请单实例锁并注册 `koodo-reader` 协议。

候选方案：另设测试入口，在加载任何官方主进程模块之前，创建全新目录并显式设置 `appData`、`userData`、`sessionData`、日志、临时和崩溃目录。测试数据使用 `<test-root>/profile/uploads/data`，只放合成样本；验证 `storageLocation`、数据库路径、IPC 返回路径均在测试根内，再允许写入。隔离测试还需拦截协议注册、更新下载安装、云同步和外部账户调用，并处理单实例锁。仅传 `--user-data-dir` 或只改书库路径不能视为完整隔离证据。此入口尚未实现或运行。

Electron 的路径覆盖须发生在相应初始化之前，参见[官方 app 文档](https://www.electronjs.org/docs/latest/api/app#appsetpathname-path)。

## 安装目录增量调试候选方案

用户允许后续使用现有安装目录省去重复安装。候选流程为：只在仓库修改源码，保留上一个可用的 `app.asar`、`app.asar.unpacked` 和版本/哈希清单，退出目标程序后替换成匹配的构建产物；先在独立副本及测试 profile 验证，失败时恢复程序资源。

限制：`app.asar.unpacked` 含原生依赖，必须与目标 Electron 版本、架构和 ABI 匹配；单独替换不匹配资源不能保证可运行。程序回滚不能自动回滚数据库 schema；涉及数据格式变化前另行设计备份与回滚。本轮不替换安装资源、不运行卸载程序、不修改真实 profile。

| ADR-011 | 按完整书籍文件 SHA256 关联设备；笔记/书签 UUID 另建映射 | 不假设时间戳 key 全局唯一；本机路径、封面、原始 key 映射不上传。相同内容的本机重复书籍先拒绝同步，避免混合统计 |
| ADR-012 | 向量版本与多值寄存器；删除并发优先，其他冲突按稳定规则暂选并保留双方 | 设置中可选择冲突版本产生因果后继。上传成功并不等于本地已经应用，只有成功应用才确认因果上下文 |
| ADR-013 | 统计使用去重历史基线 + 设备增量计数器 | 首次旧统计取 max，接入后的设备增量相加；本地清空/减少不是云端统计复位。见协议限制，不能声称旧历史的独立部分已精确合并 |
| ADR-014 | 同步时关闭阅读窗口，互斥阻止新 reader；数据库继续使用 database-command | 数据库以整表批次 CAS 和事务写入，跨表失败逆向 CAS 回滚。回滚失败则标记必须恢复并停自动同步 |
| ADR-015 | 每设备不可变全量快照，保留最近三代；本地同步/恢复备份各留二十份 | 验证新快照后才清理本设备旧快照；MEGA 旧文件移到云端回收站。实体 tombstone 不做时间删除 |
| ADR-016 | MEGA 会话用 Electron safeStorage 加密，缺失加密能力则拒绝保存 | 不把凭证放进通用 ConfigService 或同步数据；不保存原密码/验证码，不复用官方云凭证 |
| ADR-017 | `xyz.960960.koodo.custom` / Koodo Reader Custom / `%APPDATA%\koodo-reader-custom` | 不自动复制、迁移或读取官方 profile。运行时设置发生在 Store/日志初始化之前 |
| ADR-018 | 保留上游 `koodo-reader` URI 方案，测试不注册协议 | 保持现有深链接和登录回调兼容；正常启动可能接管该 URI 的系统默认程序，不声称与官方 URI handler 完全隔离 |
| ADR-019 | 禁止官方安装器更新；仅准备 GitHub Windows x64 zip | UI 和主进程双重拦截，publish=null；云端编译渲染资源与原生模块，本机不 build、不安装工具链 |
| ADR-020 | Azure 每音色情绪偏好；相同音色的多个角色共用偏好 | 只使用当前 StyleList；中性省略 express-as；官方多角色分析授权逻辑、其他 Provider 保持。预览/队列共用参数，Azure 单独换算现有百分比增量 |

仍待验证的是这些默认方案在真实 Windows、MEGA/Azure 账户中的运行结果；发布协议后的不兼容调整必须升版本。
